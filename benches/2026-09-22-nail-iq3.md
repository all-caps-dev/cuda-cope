# Nail Qwen3.6-35B-A3B at UD-IQ3_S: the quant was not the problem

**Date** 2026-09-22 · **Box** see [HARDWARE.md](../HARDWARE.md) · **Result** negative, which is the point

## Hypothesis

A 3-bit quant is the lowest tier the publisher ships, and their own card says
"lowest quality of the tiers; use a larger quant if it fits". An earlier ad-hoc
check had it failing letter-counting prompts. The hypothesis was that IQ3_S is
degraded and a move to Q4 would fix it.

The model is worth naming precisely, because its name misleads. **Nail is not a
fine-tune and not an abliteration.** It is an Unsloth dynamic quant of stock
Qwen3.6-35B-A3B with a fixed chat template and an always-on terseness system
prompt written into the GGUF metadata. The publisher's own words: "We did not
quantize this, we changed one metadata string." Its blunt, short answers come
from that prompt, not from removed refusals.

The single counting failure is word counting: for "the cat sat on the mat" it
answers 5 where the answer is 6.

## Reading it

The hypothesis is **not supported**. A quant damaged by low-bit rounding does
not do arithmetic perfectly. Eight of eight on multiplication, division,
exponentiation, percentages, a rate conversion and a linear equation, all
deterministic across repetitions, is a model that is still thinking. Prose is
clean and structured output round-trips.

What remains is a single word-counting miss, which is the tokenizer weakness
every model in this family has at every quant. **Moving to Q4 would very likely
not fix it**, and would cost about 6.8 GB of system RAM, which on a 24 GB
container with 9.6 GB free is the actual constraint.

## Two things this run taught about the method

**The graded set was wrong before the model was.** The first version asked how
many vowels are in "encyclopedia" and expected 6. There are five, unless you
count y. The model answered 5 and was marked failing. The test is kept, with the
ambiguity spelled out in the prompt, because a benchmark corpus that never
catches its own bugs is not being read carefully enough.

**Phrasing moves the answer.** "How many r in 'rhubarb'?" and "How many times
does the letter r appear in 'rhubarb'?" produced different answers from the same
model at temperature 0 in the same session: the terse form failed, the explicit
form passed, each one stable across repetitions. So a counting score is partly a
measurement of your prompt. Fix the wording before comparing quants, or the
comparison measures nothing.

## The CUDA number that is not the CUDA number

`nvidia-smi` reports "CUDA Version: 13.2" on this box, and 13.2 is the release
known to produce gibberish on low-bit Qwen3.6. That reading is wrong: it is the
driver's maximum supported runtime, not the toolkit linked into the binary,
which here is 13.3.1. Checking `ldd` on the server binary and `readlink -f
/usr/local/cuda` is the difference between diagnosing a real fault and chasing a
phantom.
